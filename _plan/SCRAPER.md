# Скрейпер професійного рівня — контракт і стан

Мета: не «качає, поки не впаде», а передбачуваний інструмент: кожне джерело можна
перевірити, кожну відмову пояснити, кожен прогін повторити без втрат.

## 2. Що означає «професійний» — решта критеріїв

1. **Повага до джерела.** robots.txt, Crawl-delay, один запит на хост одночасно,
   бекоф, `Retry-After`. Без цього сайт відрубає за годину, і це не «захист», а наша помилка.
2. **Пояснюваність відмови.** Кожна невдача має код: `robots`, `blocked-waf`, `login`,
   `404`, `410`, `429`, `5xx`, `timeout`, `tls`, `format`, `too-big`, `empty-list`. У звіті —
   код і людська нотатка. «Не вийшло» — заборонене формулювання.
3. **Відтворюваність.** Один і той самий прогін на тому самому стані дає той самий результат.
   Для цього: стан на диску, канонічні URL, sha256, детермінований порядок.
4. **Зміна не ламає адаптер.** Збережена відповідь сайту = фікстура; адаптер мусить давати
   той самий набір URL на фікстурі, що й на живому сайті. Інакше «самолікування» непомітно
   змінює семантику.
5. **Спостережуваність.** По джерелу видно: скільки сторінок обійдено, скільки документів
   знайдено, скільки взято, скільки відкинуто за форматом, скільки в черзі на повтор.
6. **Структура джерела — з джерела.** Рубрики беруться з OAI `ListSets`, WP-категорій,
   sitemap-розділів; власна схема не нав'язується.

## 3. Порядок робіт (найдешевше спершу)

1. **Таксономія помилок** — один enum + поле `Code` у звіті. Дешево, одразу робить звіт читабельним.
2. **Умовні запити** — `ETag`/`Last-Modified` у курсорі джерела: повторний прогін не тягне
   незмінене (економія трафіку й часу в рази).
3. **Replay-фікстури** — по одному збереженому прикладу на родину адаптерів; тест порівнює набір URL.
4. **Структура → адаптер** — дерево рубрик із `Structure.cs` стає навігацією в застосунку
   й фільтром для вибіркового завантаження.
5. **Бюджет ввічливості** — глобальні ліміти: запитів/хв на прогін, паралельних хостів, пауза
   після серії 429.

## 4. Чого не робимо

- не обходимо оплату й логіни; закрите — позначка в каталозі
- не прикидаємось браузером там, де це заборонено robots (WebView2-обхід — лише для челенджів,
  які віддають контент публічно)
- не «ремонтуємо» адаптер мовчки: будь-яка зміна семантики — у звіті
